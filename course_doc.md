**1. Введение**

Курсова работа на тему "Разработка компилятора для учебного языка с генерацией исполняемых бинарных файлов" будет основана на работе с байт-кодом. Почему принято решение использовать байт-код? Во-первых, это быстрее, чем реализация интерпретатора через обход дерева. Во-вторых, намного проще и разумнее, чем реализация нативных инструкций для выполнения процессором. Последний описанный вариант будет гораздо быстрее работать, но на разработку такого языка требуется неоправданно много человеческих ресурсов и непрактично для курсовой работы, т.к. требуется поддержка всех возможных платформ. Реализация в курсовой работе является оптимальной по скорости работы языка, а также совместима со всеми платформами благодаря эмулятору(виртуальной машине). Это является основным преимуществом - программа на нашем языке будет выполняться на любом компьютере.

**2. Начало разработки**

14 Глава

    Код хранится в последовательностях инструкций - chunks
    Каждая инструкция начинается с одного байта opcode. Он определяет тип операции

    Размер кода нельзя знать заранее, поэтому мы используем динамический массив chunk.
    В ней code - указатель на массив байтов, count - количество элементов уже используется, capacity - указатель на массив байтов.
    reallocate - выделяет новую память, изменяет размер. Размер массива расширяется в 2 раза
    файлик дебаг для того, чтобы отслеживать наш прогресс: выводит адрес инструкции в чанке, номер строки из lines*, название инструкции
